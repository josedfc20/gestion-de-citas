# Paso 3.3 · Diseño de la API REST

> Propuesta pendiente de revisión. Esta API la usarán la web (React) y, más
> adelante, la app Android.

## 1. Convenciones

| Convención | Decisión |
|---|---|
| URL base | `/api/v1` (la versión permite cambiar la API sin romper apps antiguas) |
| Formato | JSON, nombres de campos en `camelCase` |
| Recursos | Sustantivos en plural: `/citas`, `/servicios` |
| Verbos HTTP | `GET` leer · `POST` crear · `PUT` reemplazar · `PATCH` cambiar una parte · `DELETE` eliminar |
| Fechas | ISO-8601 con zona: `2026-11-03T10:00:00+01:00`; solo fecha: `2026-11-03` |
| Dinero | Número decimal con dos decimales: `12.00` |
| Listas grandes | Paginación `?page=0&size=20` y orden `?sort=inicio,asc` |
| Errores | Problem Details (paso 3.2) |
| Documentación | Swagger UI generado automáticamente en `/swagger-ui.html` |

### Códigos de respuesta
| Código | Cuándo |
|---|---|
| 200 OK | Lectura o modificación correcta |
| 201 Created | Recurso creado (devuelve el recurso y la cabecera `Location`) |
| 204 No Content | Operación correcta sin cuerpo (por ejemplo, cerrar sesión) |
| 400 Bad Request | Datos con formato incorrecto |
| 401 Unauthorized | No ha iniciado sesión |
| 403 Forbidden | Ha iniciado sesión pero no tiene permiso |
| 404 Not Found | El recurso no existe (o no es suyo) |
| 409 Conflict | Hueco ya ocupado, email ya registrado |
| 422 Unprocessable Entity | Regla de negocio incumplida (fuera de plazo, menor de 14…) |

## 3. Ejemplos

### Reservar una cita
```http
POST /api/v1/citas
Content-Type: application/json

{
  "servicioId": 2,
  "profesionalId": 2,
  "inicio": "2026-11-03T10:00:00+01:00",
  "beneficiarioId": 1
}
```
Respuesta **201 Created**:
```json
{
  "id": 1,
  "servicio": { "id": 2, "nombre": "Corte infantil" },
  "profesional": { "id": 2, "nombre": "Luis" },
  "beneficiario": { "id": 1, "nombre": "Lucía" },
  "inicio": "2026-11-03T10:00:00+01:00",
  "fin": "2026-11-03T10:30:00+01:00",
  "precio": 12.00,
  "estado": "CONFIRMADA"
}
```
Fíjate: el cliente **no envía** el `fin` ni el `precio`; los calcula el
servidor. Nunca hay que fiarse de lo que podría manipular el navegador.

Respuesta **409 Conflict** si otro cliente lo reservó antes:
```json
{
  "type": "https://gestiondecitas/errores/hueco-no-disponible",
  "title": "Hueco no disponible",
  "status": 409,
  "detail": "Ese horario ya no está disponible. Elige otra hora."
}
```

### Consultar disponibilidad
```http
GET /api/v1/disponibilidad?servicioId=2&profesionalId=2&fecha=2026-11-03
```
```json
{
  "fecha": "2026-11-03",
  "horas": ["09:00", "09:30", "11:00", "11:30", "16:00"]
}
```

### Cambiar el estado (empleado)
```http
PATCH /api/v1/citas/1/estado
{ "estado": "COMPLETADA" }
```
Si la transición no está permitida (por ejemplo, completar antes de la hora de
inicio) → **422**.

## 4. Decisiones que conviene revisar
1. **Las acciones como recursos:** cancelar es `POST /citas/{id}/cancelacion`
   en lugar de `DELETE /citas/{id}`, porque la cita **no se borra**: cambia de
   estado y queda en el historial.
2. **`/me/...` para "lo mío":** el servidor sabe quién eres por la sesión; así
   un cliente nunca puede pedir las citas de otro cambiando un número en la URL.
3. **404 en vez de 403 para recursos ajenos:** si pides la cita de otro, la API
   responde "no existe" para no revelar que existe.
4. **Rutas `/admin/...` separadas:** es fácil proteger todo un prefijo por rol
   en Spring Security.
