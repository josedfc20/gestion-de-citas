# Paso 4.1 · B1 · Esqueleto del backend (mini propuesta)

> Aprobado el 28/10/2026. Fase 4 (Desarrollo).
> Rama: `feature/esqueleto-backend` → un PR a `main`.

B1 no implementa ningún caso de uso: deja preparada la base técnica para que
B2 a B6 solo tengan que añadir funcionalidades.

## 1. Proyecto Spring Boot (`backend/`)

- **Spring Boot 4.1** (última 4.1.x de Maven Central), **Java 21**, Maven
  Wrapper (`mvnw`, `mvnw.cmd`), `groupId` `com.gestiondecitas`,
  `artifactId` `gestion-de-citas-backend`.
- **Dependencias:** Web MVC, Data JPA, Validation, Security, Flyway (+ módulo
  de PostgreSQL), driver de PostgreSQL, Actuator (solo `/actuator/health`),
  springdoc-openapi 3.x (Swagger, la versión para Boot 4).
  Pruebas: `spring-boot-starter-test`, `spring-boot-testcontainers` y
  Testcontainers PostgreSQL.
- **Paquetes del paso 3.2**, vacíos con un `package-info.java` que dice qué
  CU irá en cada uno: `auth`, `usuario`, `beneficiario`, `servicio`,
  `empleado`, `horario`, `disponibilidad`, `cita`, `negocio`, `shared`.

Nota de la 4.1: los *starters* ahora son más pequeños (`spring-boot-starter-webmvc`,
`spring-boot-starter-flyway`…) y usa Jackson 3. No cambia nada de lo diseñado.

## 2. `shared/`

| Clase | Qué hace |
|---|---|
| `config/ClockConfig` | Bean `Clock` (UTC). Todo el código lo inyecta; las pruebas usan un reloj fijo. La zona del negocio (`Europe/Madrid`) se aplica al calcular. |
| `config/OpenApiConfig` | Título, versión y esquema `bearer` (JWT) para que Swagger tenga ya el botón *Authorize* en B2. |
| `security/SecurityConfig` | **Provisional:** sin sesiones, CSRF desactivado (API con tokens), CORS desde `CORS_ALLOWED_ORIGINS`. Públicos: Swagger y `/actuator/health`; todo lo demás **cerrado** (401) hasta que B2 añada JWT. |
| `error/GlobalExceptionHandler` | `@RestControllerAdvice` con Problem Details (RFC 9457): 400 con la lista de campos inválidos, 404, 409, 422 y 500 genérico (sin trazas ni datos al cliente). |
| `error/RecursoNoEncontradoException` (404), `HuecoNoDisponibleException` (409), `ReglaNegocioException` (422) | Excepciones de negocio que usarán los servicios. |

## 3. Base de datos

- **`docker-compose.yml`** en la raíz: `postgres:16-alpine`, lee `.env`,
  volumen con nombre (los datos sobreviven a `docker compose down`),
  *healthcheck* y puerto 5432.
- **`V1__esquema_inicial.sql`**: el esquema del paso 2.6 tal cual, con
  `refresh_token` (paso 3.4) y la restricción `EXCLUDE` contra solapes.
- **`V2__datos_iniciales.sql`**: solo la fila de `negocio` (decisión del 28/10).
  El administrador desde `ADMIN_EMAIL`/`ADMIN_PASSWORD` llega en **B2** (necesita
  BCrypt) y el perfil `demo`, en **B4/B5** (necesita servicios y horarios).
- Hibernate en modo `validate`: Flyway crea las tablas; JPA solo comprueba.

## 4. Configuración y perfiles

- `application.yml` lee las variables de entorno y, para que en Windows baste
  con el `.env`, importa `../.env` si existe (`spring.config.import`).
  Se reutilizan `POSTGRES_DB`, `POSTGRES_USER` y `POSTGRES_PASSWORD`, así no
  hay que repetir la contraseña.
- Perfil `test`: PostgreSQL de Testcontainers con `@ServiceConnection` (no usa
  la base de datos de Docker Compose).
- `.env.example` y `.gitignore` se revisan si hace falta algo nuevo.

## 5. Pruebas de B1

1. **Arranque:** el contexto arranca contra PostgreSQL de Testcontainers y
   Flyway aplica V1 y V2.
2. **RNF-003 en la base de datos:** insertar dos citas solapadas del mismo
   profesional falla; si una está cancelada, se permite.
3. **Errores:** `@WebMvcTest` de un controlador de prueba que comprueba el
   formato Problem Details de 400, 404, 409 y 422.
4. **Seguridad provisional:** `/actuator/health` y Swagger responden; cualquier
   `/api/v1/...` devuelve 401.

## 6. CI (`.github/workflows/ci.yml`)

`./mvnw -B verify` en `backend/` (el runner de Ubuntu ya trae Docker para
Testcontainers). El job del frontend se añade en B7.
