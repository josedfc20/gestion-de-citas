Según la tabla de fases, la fase 6 tiene que **registrar las decisiones
técnicas y preparar el README**. Como en la fase 5, no empieza de cero: cada
paso dejó su propuesta en `docs/propuestas/`, hay guías de arranque y un
registro de decisiones con 68 filas. El problema es que todo eso cuenta **cómo
se fue decidiendo**, no **cómo quedó la aplicación**. Quien llegue nuevo (otro
desarrollador, un tribunal, un reclutador) tendría que leer treinta
propuestas para saber por qué la aplicación es como es. La fase consiste en
**ordenar lo que hay, poner al día lo que se quedó atrás y dar una puerta de
entrada clara**.

## 4. Decisiones que necesito de ti

1. **Formato de las decisiones técnicas.** Propongo **un archivo por decisión
   (ADR)** en `docs/decisiones/`: es el formato que se usa en los equipos, se
   enlaza desde el código y los PR, y cada uno se puede revisar por separado.
   La alternativa es una sola tabla "Decisiones técnicas" dentro de
   `Doc.docx`: más corta, pero sin sitio para las alternativas descartadas,
   que es lo que más interesa a quien revisa.
2. **Documentación de la API.** Propongo **descripciones en Swagger
   (`@Tag`, `@Operation`) y exportar `openapi.json`** con una prueba que falle
   si el archivo del repositorio no coincide con la API real (como las
   matrices de permisos). Así la documentación no se vuelve a quedar atrás.
   Toca los controllers, pero solo con anotaciones. La alternativa es poner
   al día `3.3-api-rest.md` a mano: no toca el código, pero se volverá a
   desfasar con el primer cambio.
3. **Capturas de pantalla.** Propongo sacarlas con **un script de
   Playwright** (`e2e/capturas/`, fuera de las pruebas) sobre el perfil
   `demo`, para poder repetirlas cuando cambie la web. La alternativa es que
   las hagas tú a mano: más rápido hoy, pero se quedan viejas.
4. **Manual de usuario.** Propongo **uno corto** (una sección por perfil,
   con capturas), útil para la demostración de la fase 7. La alternativa es
   dejarlo fuera y que el README baste.
5. **Licencia.** Es tu decisión. Si quieres que el repositorio sirva de
   portfolio y que cualquiera pueda mirarlo y reutilizarlo, **MIT**. Si
   prefieres reservarte los derechos, no se pone licencia y el README dice
   "Todos los derechos reservados".
