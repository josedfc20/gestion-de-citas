## 1. Del diagrama de clases a las tablas

Cada clase pasa a ser una tabla, con estas reglas:

| Regla | Ejemplo |
|---|---|
| Nombres en minúsculas y `snake_case` (convención de PostgreSQL) | `CambioEstadoCita` → `cambio_estado_cita` |
| Cada tabla tiene una clave primaria `id` autonumérica (`BIGINT GENERATED ALWAYS AS IDENTITY`) | `cita.id` |
| Cada asociación "1 a muchos" se convierte en una **clave foránea** en el lado "muchos" | `cita.empleado_id` → `empleado` |
| Cada relación "muchos a muchos" necesita una **tabla intermedia** | `empleado_servicio` |
| El enumerado se guarda como texto con una restricción `CHECK` | `cita.estado` solo admite los 4 valores de RN-008 |

## 2. Decisiones de diseño

### 2.1 Herencia de Usuario: tabla común + tabla por subtipo
- `usuario` guarda lo común y el `rol`. `cliente` y `empleado` guardan lo suyo,
  y su clave primaria es a la vez clave foránea a `usuario`.
- El administrador no tiene tabla propia porque no añade datos: basta `rol = 'ADMIN'`.
- **Alternativas descartadas:** una sola tabla con todo (muchas columnas vacías
  según el rol) o tres tablas sin la común (el login tendría que buscar en tres
  sitios y el email único sería difícil de garantizar).
- En Spring Boot esto corresponde a `@Inheritance(strategy = JOINED)`.

### 2.2 Email único sin distinguir mayúsculas
`Ana@Correo.com` y `ana@correo.com` son el mismo correo: el índice único se
hace sobre `lower(email)`.

### 2.3 Dinero y fechas
- Dinero en `NUMERIC(10,2)`: exacto, sin errores de redondeo.
- Fechas con hora en `TIMESTAMPTZ` (con zona horaria) y la zona del negocio en
  `negocio.zona_horaria`. Evita errores con el cambio de hora de verano.

### 2.4 Horario general y ajustes en la misma tabla
`tramo_horario.empleado_id` vacío (`NULL`) significa horario general; relleno,
ajuste de ese empleado. Igual en `dia_cierre`.

### 2.5 La regla más importante: nada de citas solapadas (RNF-003)
La restricción `no_solape_profesional` hace que **la propia base de datos**
rechace una cita si se solapa con otra activa del mismo profesional.

- Aunque dos clientes pulsen "Reservar" en el mismo milisegundo, solo una de
  las dos reservas se guarda; la otra recibe un error y la aplicación muestra
  "Esa hora ya no está disponible" (diagrama de secuencia de Reservar cita).
- Solo cuentan las citas `CONFIRMADA` o `COMPLETADA`: una cita cancelada libera
  su hueco automáticamente.
- El rango `[inicio, fin)` incluye el inicio y excluye el fin, así una cita de
  10:00 a 10:30 y otra de 10:30 a 11:00 **no** chocan.
- Necesita la extensión `btree_gist`, incluida en PostgreSQL.

### 2.6 Qué valida la base de datos y qué la aplicación
| La base de datos garantiza | La aplicación (Spring Boot) valida |
|---|---|
| Campos obligatorios, unicidad del email y del nombre del servicio | Edad de 14 años o más (RN-006) y beneficiario menor de 14 (RN-007) |
| Precio no negativo, inicio < fin, estados válidos | Duración múltiplo del intervalo (RN-011) |
| Sin solapes de un mismo profesional (RNF-003) | Plazo de 24 h para cancelar (RN-004) y antelación de 60 días (RN-009) |
| Integridad de las claves foráneas | Transiciones de estado permitidas (CU-015) y motivo de cancelación |

Regla práctica: la base de datos protege lo que **nunca** debe romperse; la
aplicación aplica las reglas de negocio que dependen de la fecha actual o de la
configuración.

### 2.7 Índices
- `cita (empleado_id, inicio)`: agenda del empleado y cálculo de disponibilidad.
- `cita (cliente_id, inicio)`: "Mis citas".
- `cambio_estado_cita (cita_id)`: historial de una cita.

### 2.8 Borrado de datos y RGPD
- Servicios y empleados no se borran: `activo = false`.
- Si un cliente pide eliminar su cuenta (CU-004), no se borran sus citas (son
  historial del negocio): se **anonimizan** sus datos personales (nombre,
  email, teléfono) y se desactiva la cuenta.

## 3. Qué falta para la fase 4
El borrador SQL se convertirá en **migraciones** versionadas (por ejemplo con
Flyway) para que la base de datos se pueda recrear igual en cualquier equipo.
Esa decisión se tomará en la fase 3 (Arquitectura).
