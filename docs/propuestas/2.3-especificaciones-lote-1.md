# Paso 2.3 · Especificación de casos de uso — Lote 1: cuenta de usuario

> Propuesta pendiente de revisión. Plantilla basada en la que ya usabas, con
> un campo nuevo: **Requisitos relacionados** (trazabilidad).

## CU-001 · Registrarse

| Campo | Descripción |
|---|---|
| Actor principal | Visitante |
| Requisitos relacionados | RF-001, RN-006, RNF-001, RNF-007 |
| Objetivo | Crear una cuenta de cliente. |
| Precondiciones | No existe una cuenta con el mismo correo electrónico. |
| Disparador | El visitante selecciona "Registrarse". |
| Datos de entrada | Nombre, apellidos, correo, teléfono, fecha de nacimiento, contraseña, confirmación de contraseña y aceptación de la política de privacidad. |
| Flujo principal | 1. El visitante abre el formulario de registro. 2. Introduce sus datos y su contraseña dos veces. 3. Acepta la política de privacidad. 4. El sistema valida el formato de los datos. 5. Comprueba que el correo no esté registrado. 6. Comprueba que tiene 14 años o más. 7. Guarda la contraseña con hash y crea la cuenta con rol Cliente. 8. Informa del registro correcto y muestra el inicio de sesión. |
| Flujo alternativo 1 | Correo ya registrado: se informa y no se crea la cuenta. |
| Flujo alternativo 2 | Las contraseñas no coinciden o no cumplen la política mínima: se indica el error sin borrar el resto de datos. |
| Flujo alternativo 3 | Menor de 14 años: se informa de que no puede crear cuenta y de que un adulto puede reservar por él (RN-007). |
| Flujo alternativo 4 | No acepta la política de privacidad: no se puede completar el registro. |
| Postcondición | Existe una cuenta de cliente activa. |

## CU-002 · Iniciar sesión

| Campo | Descripción |
|---|---|
| Actor principal | Usuario (cliente, empleado o administrador) |
| Requisitos relacionados | RF-002, RNF-002, RN-005 |
| Objetivo | Acceder al sistema con sus credenciales. |
| Precondiciones | El usuario tiene una cuenta activa. |
| Disparador | Selecciona "Iniciar sesión". |
| Datos de entrada | Correo y contraseña. |
| Flujo principal | 1. Introduce correo y contraseña. 2. El sistema valida las credenciales. 3. Identifica el rol. 4. Inicia la sesión. 5. Muestra la pantalla principal de su rol. |
| Flujo alternativo 1 | Credenciales incorrectas: mensaje genérico ("correo o contraseña no válidos"), sin revelar cuál falla. |
| Flujo alternativo 2 | Cuenta inactiva o bloqueada: se informa y no se inicia sesión. |
| Flujo alternativo 3 | Empleado con contraseña temporal: el sistema le obliga a cambiarla antes de continuar (RN-005). |
| Flujo alternativo 4 | Elige "¿Olvidaste tu contraseña?": continúa en CU-020. |
| Postcondición | El usuario queda autenticado con los permisos de su rol. |

## CU-003 · Cerrar sesión

| Campo | Descripción |
|---|---|
| Actor principal | Usuario |
| Requisitos relacionados | RF-002 |
| Objetivo | Terminar la sesión de forma segura. |
| Precondiciones | El usuario ha iniciado sesión. |
| Disparador | Selecciona "Cerrar sesión". |
| Flujo principal | 1. El sistema invalida la sesión. 2. Muestra la página de inicio pública. |
| Flujo alternativo 1 | La sesión ya había caducado: se muestra directamente la página de inicio. |
| Postcondición | La sesión deja de ser válida; las páginas privadas exigen volver a iniciar sesión. |

## CU-004 · Modificar perfil

| Campo | Descripción |
|---|---|
| Actor principal | Usuario |
| Requisitos relacionados | RF-016, RNF-007 |
| Objetivo | Actualizar sus datos personales o su contraseña. |
| Precondiciones | El usuario ha iniciado sesión. |
| Disparador | Selecciona "Mi perfil". |
| Datos de entrada | Nombre, apellidos, teléfono, correo; opcionalmente contraseña actual y nueva. |
| Flujo principal | 1. El sistema muestra los datos actuales. 2. El usuario los modifica. 3. El sistema los valida. 4. Guarda los cambios. 5. Confirma la actualización. |
| Flujo alternativo 1 | Nuevo correo ya usado por otra cuenta: se informa y no se guarda. |
| Flujo alternativo 2 | Cambio de contraseña con la contraseña actual incorrecta: se rechaza. |
| Flujo alternativo 3 | El usuario solicita eliminar su cuenta (RNF-007): se pide confirmación y se eliminan o anonimizan sus datos personales. |
| Postcondición | Los datos del perfil quedan actualizados. |

## CU-020 · Recuperar contraseña

| Campo | Descripción |
|---|---|
| Actor principal | Usuario |
| Requisitos relacionados | RF-018, RNF-001 |
| Objetivo | Volver a acceder si ha olvidado la contraseña. |
| Precondiciones | Ninguna. |
| Disparador | Selecciona "¿Olvidaste tu contraseña?" en CU-002. |
| Datos de entrada | Correo; después, la nueva contraseña. |
| Flujo principal | 1. Introduce su correo. 2. El sistema muestra siempre el mismo mensaje ("si el correo existe, recibirás un enlace"). 3. Si la cuenta existe, envía un enlace de un solo uso que caduca en 30 minutos. 4. El usuario abre el enlace e introduce la nueva contraseña dos veces. 5. El sistema la guarda con hash e invalida el enlace. 6. Confirma el cambio. |
| Flujo alternativo 1 | Enlace caducado o ya usado: se informa y se ofrece solicitar uno nuevo. |
| Flujo alternativo 2 | Las contraseñas no coinciden: se indica el error. |
| Postcondición | La contraseña queda cambiada y el enlace deja de ser válido. |
