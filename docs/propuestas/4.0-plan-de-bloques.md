# Paso 4.0 · Plan de bloques de la fase 4 (Desarrollo)

> Aprobado el 28/10/2026 (Spring Boot 4.1, datos iniciales y orden backend → web).

## 1. Cómo trabajaremos cada bloque

- **Un hilo por bloque.** Cada hilo empieza con una mini propuesta del bloque
  (qué clases, endpoints y pruebas) que apruebas antes de escribir código.
- **Una rama `feature/...` y uno o varios PR pequeños por bloque.** Nada va
  directo a `main`; tú revisas cada PR y lo fusionas cuando la CI está en verde.
- **Cada bloque trae sus propias pruebas** (unitarias con JUnit 5 + Mockito e
  integración con Testcontainers). La fase 5 añadirá después las pruebas de
  extremo a extremo, la cobertura y la revisión general.
- **Al cerrar cada bloque** se actualizan `AGENTS.md` y `docs/Doc.docx`.
- **Orden: primero el backend, luego la web.** Así la web se construye sobre
  una API ya probada y documentada en Swagger.

## 3. Decisiones que necesito de ti

1. **Versión de Spring Boot.** En el paso 3.1 aprobamos Spring Boot 3. Hoy la
   línea actual es la **4.1** (Maven Central ya publica la 4.1.2) y la 3.5 está
   al final de su soporte gratuito. Propongo **Spring Boot 4.1**: el proyecto
   durará meses y es lo que pedirán las empresas. La contrapartida es que hay
   menos tutoriales que para la 3.x. Si prefieres no cambiar lo aprobado, uso
   la 3.5.
2. **Datos iniciales.** Propongo una migración `V2__datos_iniciales.sql` solo
   con el registro de `negocio`, y que el **primer administrador** se cree al
   arrancar a partir de variables de entorno (`ADMIN_EMAIL`, `ADMIN_PASSWORD`),
   para no guardar ninguna contraseña en Git. Los datos de demostración
   (servicios y empleados de la peluquería) irían en un perfil `demo` aparte.
3. **El orden** (backend completo y después la web). La alternativa es hacer
   cada funcionalidad de punta a punta (API + pantalla), que se ve antes en el
   navegador pero mezcla más cosas en cada PR.
