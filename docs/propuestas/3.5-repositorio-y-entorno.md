> Aprobado el 26/10/2026. Último paso de la fase 3.

## 1. Un solo repositorio en GitHub (monorepo)

Nombre propuesto: **`gestion-de-citas`**. Backend, frontend y documentación
juntos: un cambio que toca la API y la web va en un solo *pull request*, y quien
vea tu GitHub entiende el proyecto completo de un vistazo.

```
gestion-de-citas/
├── AGENTS.md                 ← reglas para asistentes de IA (el que ya tenemos)
├── README.md                 ← presentación del proyecto (portafolio)
├── docker-compose.yml        ← PostgreSQL local con un comando
├── .env.example              ← variables necesarias, sin valores reales
├── .gitignore
├── .github/workflows/ci.yml  ← compila y ejecuta las pruebas en cada push
├── backend/                  ← Spring Boot (Maven)
│   ├── pom.xml
│   └── src/main/java/com/gestiondecitas/...   (paquetes del paso 3.2)
│       src/main/resources/db/migration/V1__esquema_inicial.sql
├── frontend/                 ← React + TypeScript (Vite)
│   ├── package.json
│   └── src/...
└── docs/
    ├── Doc.docx
    ├── diagramas/
    └── propuestas/
```

Tu carpeta actual `GestionDeCitas` pasaría a ser la carpeta `docs/` (más
`AGENTS.md` en la raíz).

## 2. Forma de trabajar con Git

| Tema | Propuesta |
|---|---|
| Ramas | `main` siempre estable. Cada tarea en su rama: `feature/reservar-cita`, `fix/cancelacion-plazo` |
| Integración | *Pull request* a `main`: tú lo revisas (tu papel de tech lead) y se fusiona cuando las pruebas pasan |
| Mensajes de commit | *Conventional Commits*: `feat: reservar cita`, `fix: plazo de 24 h`, `docs: actualizar AGENTS.md`, `test: ...` |
| Pruebas automáticas | GitHub Actions ejecuta las pruebas del backend y del frontend en cada push y en cada PR |
| Secretos | Nunca en Git: `.env` está en `.gitignore`; solo se sube `.env.example` |

Así el ciclo de las reglas del proyecto (propuesta → revisión → implementación →
revisión de código) queda reflejado en GitHub, que es justo lo que miran las
empresas.

## 4. Arrancar el proyecto en local (cuando exista)

```bash
docker compose up -d          # 1. PostgreSQL en el puerto 5432
cd backend && ./mvnw spring-boot:run   # 2. API en http://localhost:8080
cd frontend && npm install && npm run dev   # 3. Web en http://localhost:5173
```

Swagger quedará en `http://localhost:8080/swagger-ui.html`.
